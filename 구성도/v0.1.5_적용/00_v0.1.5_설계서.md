> 적용 기준: [구성도.md](../구성도.md) (§0 목적, §2.1~2.10 구성 요소, §4 설계 선택지)
> 문서 상태: **워크스루 대상물(초안 D1)** — 이 문서는 [02_시나리오_트레이스.md](02_시나리오_트레이스.md)의
> 정적 검토를 거쳤으며, 검토에서 발견된 결함은 [03_결함기록부.md](03_결함기록부.md)에 별도 기록되어 있다.

## 1. 목적 및 범위

구성도 §0에 명시된 4개 목적을 v0.1.5의 기능 요구사항으로 확정한다.

| ID | 목적 | v0.1.4 현황 | v0.1.5 목표 |
|---|---|---|---|
| G-1 | 대상 기업을 멀티에이전트로 다각도 분석하여 인사이트 도출 | 없음 (단일 LLM 호출만) | 오케스트레이터 + 역할별 서브에이전트 4종 |
| G-2 | 특정 형식의 재무제표 분석 | 없음 (`.xlsx`를 평문 표로 덤프만) | 계정과목 매핑 + 지표 산출 + 위키 저장 |
| G-3 | 뉴스 검색을 위한 키워드 분석 | 없음 | 기업/이슈 기반 검색 키워드 세트 생성 |
| G-4 | 정해진 형식의 엑셀 생성 툴 | 없음 (읽기 전용 `calamine`) | 템플릿 기반 `.xlsx` 출력 |

**범위 밖(v0.1.5 비대상)**: 벡터 임베딩 검색, 외부 뉴스 API 실호출, 스트리밍 응답, 설치 패키징.

## 3. 데이터 구조 변경

### 3.1 `WikiEntry` 확장 (`wiki.rs`)

구성도 §2.4가 요구하는 **관계의 종류**와 **신뢰도 등급**을 반영한다.

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum RelationKind {
    Basis,        // "이것을 근거로 만들었다"
    Reference,    // "이것을 참조한다"
    Contradicts,  // "이것과 모순된다"
    PartOf,       // "이것의 하위 항목이다"
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WikiRelation {
    pub target_id: String,
    pub kind: RelationKind,
}

#[derive(Debug, Clone, Copy, Serialize, Deserialize)]
pub enum Confidence {
    Stated,     // 원본에 명시됨 (확실)
    Inferred,   // 합리적 추론 (중간)
    Uncertain,  // 근거 부족 (낮음)
}

pub struct WikiEntry {
    pub id: String,
    pub title: String,
    pub summary: String,
    pub body: String,
    pub tags: Vec<String>,
    pub source: String,
    pub relations: Vec<WikiRelation>,   // 기존 related_ids 대체
    pub confidence: Confidence,          // 신규
    pub company: Option<String>,         // 신규: 기업 스코프
    pub period: Option<String>,          // 신규: 회계 기간 (예: "2025-FY")
    pub created_at: String,
    pub updated_at: String,
}
```

### 3.2 재무제표 표준 모델 (`finance.rs` 신규)

```rust
pub struct FinancialStatement {
    pub company: String,
    pub period: String,
    pub unit: String,               // "백만원" 등
    pub lines: Vec<AccountLine>,    // 계정과목별 금액
}

pub struct AccountLine {
    pub raw_label: String,          // 원본 시트에 적힌 계정과목명 그대로
    pub canonical: Option<Account>, // 표준 계정으로 매핑된 결과
    pub amount: i64,
}

pub enum Account {  // 특정 형식 = 아래 표준 계정 집합
    Revenue, OperatingProfit, NetIncome,
    TotalAssets, TotalLiabilities, TotalEquity,
    CurrentAssets, CurrentLiabilities,
    OperatingCashFlow,
}

pub struct Metrics {   // 산출 지표
    pub operating_margin: Option<f64>,
    pub net_margin: Option<f64>,
    pub roe: Option<f64>,
    pub debt_ratio: Option<f64>,
    pub current_ratio: Option<f64>,
}
```

## 4. 신규 모듈 상세

### 4.1 `agents.rs` — 에이전트 오케스트레이션 (구성도 §2.8)

Supervisor 패턴. 오케스트레이터가 역할별 서브에이전트를 호출하고 결과를 종합한다.

```
                    ┌──────────────────────────┐
   "삼성전자 분석"  →│  Supervisor (오케스트레이터) │
                    └────────────┬─────────────┘
                                 │ 병렬 위임
          ┌──────────────┬───────┴───────┬──────────────┐
          ▼              ▼               ▼              ▼
   ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
   │ 재무 에이전트 │ │ 뉴스 에이전트 │ │ 산업 에이전트 │ │  (위키 조회) │
   │  finance    │ │  news       │ │  market     │ │            │
   └──────┬─────┘ └──────┬─────┘ └──────┬─────┘ └──────┬─────┘
          └──────────────┴───────┬───────┴──────────────┘
                                 ▼
                    ┌──────────────────────────┐
                    │  종합 에이전트 (synthesis)  │  인사이트 도출
                    └────────────┬─────────────┘
                                 ▼
                    위키 저장 + 리포트 + (선택) 엑셀 출력
```

```rust
pub enum AgentRole { Finance, News, Market, Synthesis }

pub struct AgentTask {
    pub role: AgentRole,
    pub company: String,
    pub context: Vec<WikiEntry>,   // 라우터가 골라준 관련 페이지
}

pub struct AgentOutput {
    pub role: AgentRole,
    pub findings: String,
    pub confidence: Confidence,
}

/// 오케스트레이터: 4개 역할을 돌려 결과를 모은 뒤 종합 에이전트에 넘긴다.
pub async fn analyze_company(
    app: &AppHandle,
    wiki: &WikiState,
    model: &str,
    num_ctx: u32,
    company: &str,
) -> Result<String, String> {
    let mut outputs = Vec::new();
    for role in [AgentRole::Finance, AgentRole::News, AgentRole::Market] {
        outputs.push(run_agent(app, wiki, model, num_ctx, role, company).await?);
    }
    synthesize(app, wiki, model, num_ctx, company, &outputs).await
}

/// 개별 서브에이전트: 역할별 프롬프트로 Ollama를 호출하고 결과를 위키에 저장한다.
async fn run_agent(...) -> Result<AgentOutput, String> {
    let messages = build_role_prompt(role, company, &context);
    let result = queue::run_queued(app, "agent", preview, ollama::chat(model, &messages, num_ctx)).await?;
    wiki::save(...);   // 역할별 분석 결과를 페이지로 저장
    Ok(AgentOutput { .. })
}
```

전체 흐름은 오케스트레이터 자체도 하나의 큐 작업으로 실행한다:

```rust
// main.rs 커맨드
queue::run_queued(app, "orchestrator", preview, agents::analyze_company(...)).await
```

### 4.2 `tools.rs` — 도구함 (구성도 §2.9)

### 4.4 `excel.rs` — 정해진 형식 엑셀 생성 (G-4)

`rust_xlsxwriter` 크레이트를 신규 추가한다 (현행 `calamine`은 **읽기 전용**이라 생성 불가).

```toml
rust_xlsxwriter = "0.79"
```

출력 템플릿 (고정 형식):

| 시트 | 내용 |
|---|---|
| `요약` | 기업명, 기준일, 종합 인사이트 |
| `재무지표` | 계정과목 / 금액 / 전기대비 / 지표 |
| `뉴스키워드` | 키워드 / 분류 / 우선순위 |
| `근거` | 항목 / 신뢰도 / 출처 위키 페이지 ID |

## 7. 운영 규칙 문서 초안 (`AGENTS.md`, §2.10)

```markdown
# noriter-ai 운영 규칙

## 질의
- 질문을 받으면 위키 전체 본문을 넣지 말고 INDEX.md(또는 인덱스층)를 먼저 읽는다.
- 관련 페이지 2~3개만 골라 본문을 펼친다.

## 저장
- 재무 수치는 원본에 명시된 값만 Stated로 기록한다. 계산으로 도출한 지표는 Inferred.
- 근거를 찾지 못한 서술은 Uncertain으로 표시하고 단정하지 않는다.

## 산출물
- 리포트에는 항상 신뢰도 등급을 함께 표기한다.
```

## 8. 미결 사항 (D1 시점)

- (O-1) 뉴스 에이전트가 실제 네트워크 검색을 하는가, 키워드만 생성하는가 — 목적 문구만으로는 불확정.
- (O-2) 기존 `index.json`의 `related_ids` → `relations` 마이그레이션 방식 미정.
- (O-3) 오케스트레이터 실행 중 사용자 취소 경로 미설계.
