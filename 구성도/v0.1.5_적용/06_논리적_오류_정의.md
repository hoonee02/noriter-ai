# 논리적 오류 정의 문서

> 이 문서는 **논리오류 검증 에이전트**(00_v0.1.5.1_설계서.md §7.2)가 검출 대상으로 삼는
> 논리적 오류 목록과 정의를 담는다. 사용자가 제시한 나무위키 문서 목록을 **오류 이름의 출처**로만
> 참고하고, 정의·예시는 일반적으로 통용되는 논리학·수사학 지식을 바탕으로 이 문서에서 새로
> 작성했다(특정 문서의 서술을 그대로 옮기지 않음). 각 항목 끝의 링크는 더 깊은 내용이 필요할 때
> 사람이 직접 확인하는 용도다.
>
> 기존 검증 에이전트에 있던 4대 논리오류(원인-상관관계 착각/성급한 일반화/흑백논리·거짓 딜레마/
> 인신공격·논점일탈)는 **이 문서로 전면 대체되어 폐기**되었다 — 아래 목록에 해당 개념들이
> 더 넓은 분류 체계 안에 다시 포함되어 있다.

## 분류 체계 (총칭 개념)

나무위키의 표준적인 논리적 오류 분류 체계를 그대로 뼈대로 삼는다 — 오류를 우선 **형식적 오류**와
**비형식적 오류**로 나누고, 비형식적 오류를 다시 4갈래로 세분한다. 아래 개별 오류들은 모두
이 6개 범주(형식적 오류 1개 + 비형식적 오류 산하 4개 + 총칭 자체) 중 하나 이상에 속한다.

| 범주 | 정의 |
|---|---|
| **논리적 오류** (총칭) | 전제로부터 결론을 이끌어내는 추론·논증 과정에 결함이 있어, 결론이 타당하게 뒷받침되지 않는 모든 경우를 통칭하는 최상위 개념 |
| **형식적 오류** | 전제가 모두 참이라 하더라도, 추론에 사용된 논리 규칙(형식) 자체가 타당하지 않아 결론이 필연적으로 따라 나오지 않는 오류 — 연역 논증의 구조 결함 |
| **비형식적 오류** | 논증의 형식 자체는 문제없어 보이지만, 전제의 내용·맥락·언어 사용·심리적 설득 방식 등에서 결함이 있는 오류들의 통칭 |
| ├ **귀납적 오류** | 제한된 사례·관찰로 일반적 결론을 이끌어내는 귀납 추론에서, 근거가 결론을 충분히 뒷받침하지 못하는데도 결론을 받아들이는 오류 |
| ├ **심리적 오류** | 논증 내용 자체가 아니라 감정·권위·대중심리 등 심리적 요인에 기대어 결론을 정당화하려는 오류 |
| ├ **언어적 오류** | 단어의 모호성·다의성·문법 구조 등 언어 사용 문제에서 비롯되는 오류 |
| └ **자료적 오류** | 전제로 쓰인 사실·자료 자체가 틀렸거나 부적절해서 생기는 오류 |

## 프롬프트 공급 방식 (E-1 결정, 2026-07-26)

**사용자 결정**: 26종을 **전량 주입**한다. 카테고리별 분할이나 선택적 주입을 하지 않는다.
시간이 더 걸리더라도 전체 검출을 시도해 **데이터를 먼저 쌓는다**는 판단이다.

### 다만 VRAM 6GB 제약과 같은 예산을 다툰다

[08 §4.3](08_MapReduce_청킹_시험적용.md)에서 확인했듯 `num_ctx`는 VRAM 상한 안에서 하나로 고정되며,
모든 에이전트가 그 예산을 나눠 쓴다. 26종 정의가 예산을 많이 차지할수록 **정작 검사할 findings가
들어갈 자리가 줄어든다** — 정의는 다 넣었는데 검사 대상이 잘려나가면 검출률이 오히려 떨어진다.

### 조치 — 완전판과 프롬프트판을 분리한다

| 판본 | 용도 | 포함 내용 |
|---|---|---|
| **완전판** (이 문서 위 표) | 사람이 읽고 유지보수 | 오류명 · 분류 · 정의 · 판별 포인트 · 참고 링크 |
| **프롬프트판** | 논리오류 검증 에이전트에 주입 | 오류명 · 한 줄 판별 기준만 |

프롬프트판은 참고 링크·분류 설명·서술형 정의를 걷어내고 **판별에 직접 쓰이는 최소 정보만** 남긴다.
"전량 주입"이라는 결정을 지키면서도 토큰을 줄이는 방법이다.

```rust
pub mod logic_fallacy_agent {
    /// 26종 전량을 프롬프트판 형식으로 직렬화한다.
    /// 완전판(이 문서의 표)이 아니라 판별 기준만 추린 축약본을 쓴다.
    fn fallacy_checklist_prompt() -> String { .. }
}
```

> **두 판본의 동기화**: 완전판에 오류를 추가·삭제하면 프롬프트판과 `FallacyType` 열거값을
> **함께** 갱신해야 한다. 문서-코드 1:1 대응 원칙이 이제 3자(완전판 · 프롬프트판 · 열거값)
> 대응으로 확장된다.

### 실측 후 재검토 (O-30)

전량 주입이 실제 `num_ctx` 안에서 성립하는지는 측정해봐야 안다. 프롬프트판으로도 예산을 넘기면
그때 카테고리별 분할(형식/귀납/심리/언어/자료 5분할)로 후퇴하는 것을 검토한다 — 다만 **지금은
데이터 축적을 우선한다는 결정에 따라 전량 주입으로 시작**한다.

## 문서 갱신 규칙

- 새 오류 유형을 추가할 때는 이 표에 행을 추가하고, `FallacyType` 열거값(00_v0.1.5.1 §7.2)에도
  대응 항목을 추가한다 — 문서와 코드가 항상 1:1로 대응해야 논리오류 검증 에이전트가 이 문서를
  "그대로 참고해 검출"할 수 있다.
- "총칭" 행(분류 체계 자체를 가리키는 7개 항목)은 검출 대상 오류가 아니라 분류용 카테고리이므로,
  에이전트가 실제로 플래그를 붙이는 대상에서는 제외한다.
