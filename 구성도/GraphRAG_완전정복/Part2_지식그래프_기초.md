# Part 2. 지식 그래프 기초 이해

> 원본: [neo4j] GraphRAG 완전 정복 - 초보자를 위한 지식 그래프 기반 RAG 시스템
> https://wikidocs.net/book/18976

## 2-1. 그래프란 무엇인가?
원본: https://wikidocs.net/319193

- 데이터 구조로서의 그래프는 노드(Node, 점)와 엣지(Edge, 선)로만 구성되는 단순한 개념. 가족 관계도가 가장 친숙한 예.
- 엣지에 방향을 부여하면 방향 그래프(Directed Graph, 예: 조직도의 "관리한다" 방향), 엣지에 라벨을 붙이면 관계의 의미가 명확해진다(예: "세종대왕-[아들]->문종", "세종대왕-[창제]->한글").
- 일상의 그래프 예: 소셜미디어(팔로우), 지도(도로/경로), 웹(하이퍼링크), 조직도(보고체계), 추천시스템(구매/좋아요).
- 그래프가 유용한 3가지 상황: 관계 질의("A와 B의 관계는?"), 경로 탐색(최단 경로 찾기), 연결된 그룹 탐색.
- **관계형 DB vs 그래프 DB** 비교가 핵심: 직원-부서 테이블 구조에서 "김철수의 팀장은?"을 구하려면 JOIN을 여러 번 거쳐야 하지만, 그래프에서는 관계를 따라가기만 하면 된다. 질의가 복잡해질수록(예: "같은 부서 동료가 참여한 프로젝트 중 외부 협업 건의 담당자 연락처") 관계형 DB는 다중 JOIN이 필요한 반면 그래프는 경로 탐색으로 자연스럽게 해결.
- 비교표: 정형 데이터·단순 조회는 관계형 DB가 유리, 복잡한 관계 분석·경로 탐색·유연한 스키마는 그래프 DB가 유리.
- 노드와 엣지 모두 속성(Property)을 가질 수 있다 — 예: [김철수] 노드는 나이/직급/입사일 속성을, [김철수-근무->개발팀] 엣지는 시작일/역할/평가등급 속성을 가질 수 있음.

## 2-2. 지식 그래프의 핵심 개념
원본: https://wikidocs.net/319194

- 지식 그래프(Knowledge Graph)는 일반 그래프에 "의미(Semantics)"를 더한 것. 노드는 개념/사물을, 엣지는 관계의 의미를 나타낸다.
- 3대 구성요소: **엔티티(Entity)** = 노드(식별 가능한 개체, 예: 세종대왕/한글/조선), **관계(Relationship)** = 엣지(방향과 속성을 가질 수 있음), **속성(Property)** = 엔티티/관계에 붙는 부가 정보(예: 세종대왕의 생몰년, "창제" 관계의 창제년도).
- **트리플(Triple)**: 지식 그래프의 최소 단위로 (주어, 관계, 목적어) 구조. 예: (세종대왕, 창제, 한글). 복잡한 문장도 여러 트리플의 조합으로 분해해 표현할 수 있다.
- **스키마(Schema)**는 어떤 종류의 엔티티/관계가 존재할지 정의하는 설계도 역할.
- 실제 사례로 Google Knowledge Graph(2012년 공개 당시 5억 엔티티, 35억 트리플 규모, 검색 결과 우측 정보 패널의 근거)와 Wikidata(위키피디아 기반 개방형 지식 그래프, 1억+ 항목, 15억+ 관계)를 소개. LinkedIn(직무/기술), Amazon(상품/추천), Netflix(콘텐츠/배우), Uber(장소/경로) 등 기업들이 내부적으로 지식 그래프를 활용한다는 점도 언급.
- 지식 그래프로 가능한 것: 연관 검색(관련 인물/이론 추천), 자연어 질의응답(관계 경로를 따라 답 찾기), 추천 시스템(공통 관계 기반 추천).

## 2-3. 지식 그래프가 검색을 개선하는 방법
원본: https://wikidocs.net/319196

- 키워드 검색 재확인 실험: "김철수 팀장이 담당하는 프로젝트는?" 질문에서, 사실이 3개 문서(소속/팀장/담당 프로젝트)에 분산되어 있으면 키워드 매칭만으로는 어떤 검색어를 써도 연결이 안 되지만, 지식 그래프는 [김철수]→(소속)→[AI팀]→(팀장)→[박영희]→(담당)→[BERT 프로젝트] 경로를 그대로 따라가 답을 찾는다.
- **1홉 vs 다중 홉(Multi-hop)**: 1홉은 직접 연결된 관계 질의("세종대왕이 창제한 것은?"), 다중 홉은 여러 관계를 거쳐야 답이 나오는 질의("한글을 창제한 왕의 아버지가 세운 기관은?" → 3단계 탐색). 홉 수가 늘수록 질문이 복합적이 된다는 표 제시(1홉: 직접 관계 / 2홉: 간접 관계 / 3홉: 복합 관계 / 4홉+: 추론 필요).
- 비즈니스 시나리오 예시: 고객 서비스(구매 노트북 → 호환 충전기 → 무선충전 지원 필터 → 리뷰 평점 경로 탐색), 공급망 리스크 관리(1차 협력사 → 2차 협력사 → 환경 규제 위반 이력 추적) 등 다중 홉 탐색이 실무에 바로 적용되는 사례.
- 지식 그래프가 특히 강한 4가지 케이스: (1) 모호한 질문 해결(맥락상 "사과"가 회사인지 과일인지 판단), (2) 불완전한 질문 이해(대화 맥락의 대명사 "그 사람"을 이전에 언급된 엔티티로 해석), (3) 비교/대조 질문(두 엔티티의 속성·관계 교집합 계산), (4) 역방향 질문(정방향 관계를 역으로 추적).
- 정량 비교표: 키워드 검색/벡터 검색(RAG)/GraphRAG를 직접 질문 정확도, 관계 질문 정확도, 다중 홉 처리 가능 여부, 설명 가능성, 일관성 축으로 비교 — GraphRAG가 관계 질문·다중 홉·설명 가능성에서 우위.
- **설명 가능성(Explainability)**의 중요성 강조: 일반 RAG는 "어딘가의 문서"라는 모호한 출처만 제시하지만, GraphRAG는 탐색한 경로 자체를 근거로 제시할 수 있어 금융·의료·법률처럼 규제 준수와 신뢰성이 중요한 분야에 유리하다.
