## 이 책이 제안하는 핵심 아이디어

이 책은 "AI를 잘 쓰는 일은 프롬프트를 길게 쓰는 게 아니라, 같은 설명을 반복하지 않고 조사·정리·
실행이 끊기지 않는 하나의 업무 흐름을 만드는 것"이라는 문제의식에서 출발한다. 단일 챗봇을 계속
붙잡고 있는 대신, 역할이 나뉜 여러 에이전트(조사형/정리형/실행형)를 하나의 "AI 팀"처럼 운영하고,
이 팀이 무엇을 기억하고 어떤 도구를 쓸지, 반복되는 업무를 어떻게 재사용 가능한 절차(Skill)로
굳힐지를 실전 운영 경험 중심으로 다룬다.

## 우리 `구성도/` 문서들과 맞닿는 지점

### 1. 기억 시스템 ↔ LLM 위키
이 책은 "AI 에이전트가 무엇을 기억해야 하는가"를 세션/메모리/프로필 같은 층위로 나누고, 외부
장기 기억으로 Obsidian 기반 위키를 활용하는 접근을 다룬다. 이는 우리가 [구성도.md](구성도.md)와
[LLM위키_완벽가이드/](LLM위키_완벽가이드/)에서 정리한 "원본(raw) → 위키(wiki) → 재사용"이라는
구조와 같은 문제의식(대화가 끝나면 사라지는 지식을 어떻게 영속화할 것인가)을 다른 각도 —
개인 AI 에이전트의 "성격/기억 관리" 운영 관점 — 에서 다룬다고 볼 수 있다.

### 2. 외부 도구 연동(MCP) ↔ 하이브리드 에이전트의 도구함
이 책은 여러 채널(메신저·문서 도구 등)과의 연동을 다루는데, 이는 [하이브리드_에이전트_RAG.md](하이브리드_에이전트_RAG.md)에서
정리한 "에이전트가 호출할 수 있는 기능을 도구(Tool)로 추상화한다"는 오케스트레이션 레이어 개념과
같은 축에 있다. 다만 이 책은 RAG 검색 도구가 아니라 실제 업무 채널·문서 도구 연동에 초점을 둔다.

### 3. 역할 분담형 멀티 에이전트 ↔ 다중 에이전트 시스템
조사형/정리형/실행형으로 에이전트 역할을 나누고 서로 다른 방식으로 실패하는 지점(예: 조사형은
결론을 서두르고, 정리형은 그럴듯하지만 근거가 약한 글을 만드는 경향)을 짚는 부분은,
[langgraph_가이드북/Part4_다중에이전트.md](langgraph_가이드북/Part4_다중에이전트.md)에서 다룬
Supervisor·Handoffs 패턴과 같은 문제(여러 에이전트가 어떻게 협업·분업하는가)를, 코드 아키텍처가
아니라 실제 운영에서 관찰된 실패 패턴 중심으로 보완한다.

### 4. 반복 업무의 절차화(Skill) ↔ 위키 문서 재사용
반복되는 업무를 "Skill"이라는 재사용 가능한 절차로 굳히는 접근은, LLM위키가 "한 번 정리한 지식을
계속 재사용한다"는 원칙과 같은 방향이다 — 다만 위키가 지식(정보)을 재사용 대상으로 삼는다면,
Skill은 절차(행동 패턴)를 재사용 대상으로 삼는다는 차이가 있다.

## 이 책의 전체 구조 (참고용 — 상세 내용은 원본 확인)

- 0장: Hermes Agent 자체의 설치·설정·비교(OpenClaw, Claude Code/Codex와의 차이) 등 기초 가이드
- 1~3장: "AI 챗봇"이 아니라 "AI 팀"을 구성하는 개념 — 메인 창구 에이전트 + 역할형(조사/정리/실행) 에이전트 운영
- 4장: 기억 시스템 설계 (session/memory/profile 구분, 외부 장기 기억으로서의 위키, RAG와의 결합)
- 5장: 외부 도구/MCP/채널 연동 자동화
- 6장: 반복 업무를 Skill로 만드는 자기 개선형 에이전트 운영
- 7장: 문서화 자동화(WikiDocs 콘텐츠 생성 파이프라인)
- 8~10장: 운영 FAQ, 보안·마이그레이션·복구, 조직 도입 시 겪는 문제
- 11장: 실전 자동화 사례 22가지 (메일 정리, 회의록 변환, SEO 콘텐츠 제작 등)
- 부록 A: 용어집, 보안 체크리스트, 설계 워크시트 등 실전 운영 도구

## 결론

이 책은 우리가 지금까지 정리한 문서들이 다루는 "지식을 어떻게 위키로 축적·재사용할 것인가"의
문제를, "그 지식을 다루는 AI 에이전트 조직을 어떻게 구성·운영할 것인가"라는 한 단계 위의 운영
관점으로 확장한 사례로 볼 수 있다. 세부 내용이 필요하면 위 원본 링크에서 관심 있는 장을 직접
찾아 읽는 것을 권한다.
